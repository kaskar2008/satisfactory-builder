# Factory Builder — проектирование завода в Satisfactory

Локальное веб-приложение для расчёта и размещения производственных цепочек Satisfactory. Пользователь выбирает рецепт, требуемый выпуск и допустимые размеры модуля. Планировщик рассчитывает станки, частоты работы, ресурсы и логистику, затем показывает завод в 3D и как граф связей.

В текущем каталоге 276 рецептов, включая стандартные и альтернативные. Поддерживаются твёрдые предметы, жидкости, несколько выходных продуктов и возврат побочных ресурсов. Сезонные рецепты исключены. Это неофициальный инструмент; результат помогает спланировать строительство в игре.

## Запуск

Нужен Node.js с поддержкой встроенного тестового раннера (рекомендуется Node.js 22 или новее) и современный браузер. Для 3D необходим WebGL. Сторонние npm-зависимости и сборка не требуются.

Из корня проекта:

```sh
node scripts/server.cjs
```

Откройте [http://127.0.0.1:5173/](http://127.0.0.1:5173/). Остановить сервер можно сочетанием `Ctrl+C`. Сервер доступен только на локальном компьютере.

Другой порт в PowerShell:

```powershell
$env:PORT = 5175
node scripts/server.cjs
```

При наличии npm можно использовать `npm start`. Запуск через HTTP нужен для штатной работы приложения, включая вычисления в Web Worker.

## Как пользоваться

1. Выберите, что производить. В списке есть поиск и категории стандартных и альтернативных рецептов. Наведение показывает полный рецепт: входы, выходы, объёмы за цикл и скорости при 100% частоте.
2. Задайте выпуск в минуту: предметы измеряются в штуках, жидкости — в м³.
3. Выберите объём конструктора чертежей или собственные ширину, длину и высоту. Укажите максимальное число этажей либо автоматический подбор, уровень лент и зазор между подъёмниками.
4. При необходимости отметьте внешние поставки промежуточных компонентов. Их производство исключается из рассчитываемой цепочки; сырьё поставляется автоматически. Обязательные готовые компоненты перечисляются отдельно.
5. Настройте модули: «Независимые модули» разделяет производство по этапам; при выключенной настройке планировщик уплотняет совместимые этапы. «Разрешить обратные связи» допускает возврат побочных ресурсов между модулями и по умолчанию выключено.
6. Нажмите «Сгенерировать завод». При замене существующего завода приложение предложит подтвердить сброс. Сначала скачайте проект, если хотите сохранить текущий вариант.
7. Изучите компоновку, производственную цепочку, поставки и проверки логистики. Если размещение не удалось, уменьшите выпуск, увеличьте доступный объём или вынесите часть производства во внешнюю поставку. Для ошибки обратных связей доступны повторная попытка с их разрешением и перевод ресурса во внешнюю поставку.

### 3D

«Объём» показывает инженерный или реалистичный low-poly вид. Можно выбрать один модуль либо все сразу, этаж и продукт. В общем виде видны подписи модулей и связи между ними. Скрытые участки труб обозначаются пунктиром.

| Действие | Управление |
| --- | --- |
| Выбрать станок, логистический узел или трассу | Левая кнопка мыши |
| Вращать камеру вокруг точки нажатия | Средняя кнопка или `Alt` + левая |
| Перемещать камеру | Правая кнопка или `Shift` + средняя |
| Масштабировать | Колесо мыши |
| Вернуть общий вид | «Камера» или `Home` |
| Фокусировать выбранный объект | `F` |

Окно выбранного объекта содержит параметры оборудования, входные и выходные скорости; у трасс — характеристики транспорта и длину пути. Кнопка «Развернуть» увеличивает полотно.

### Граф 2D

Граф показывает производственные связи, сгруппированные по модулям. Доступны два уровня детализации: «Все станки и узлы» и «Граф рецептов», объединяющий одинаковые станки. Карточки отображают основной и побочные выходы со скоростями. Возвратные связи сохраняются и прокладываются отдельными маршрутами.

Перетаскивайте свободную область для перемещения полотна, используйте колесо для масштаба. «Весь граф» вписывает схему в окно. Фильтры позволяют выбрать этап, модуль и продукт; схема выбранного этапа пересобирается с локальными входами и выходами.

Клик по карточке выделяет узел и открывает его информацию. Заголовок окна — ссылка, центрирующая граф на узле. Для смешанных поставок отдельно указаны объёмы извне и из модулей. Смена фильтра закрывает окно и снимает выделение. Выбранный режим 3D/граф сохраняется при обновлении страницы.

### Симуляция

«Симуляция» запускает производство и транспорт в обоих видах. Станки расходуют входные партии и выпускают продукты по длительности выбранного рецепта с учётом частоты. Ленты и трубы имеют ограниченную пропускную способность; время доставки зависит от длины маршрута, включая межмодульные связи.

В 3D видны движущиеся предметы и импульсы жидкости; на скрытых участках труб используются небольшие шарики. В графе частицы идут по связям, а заполнение фона карточки показывает прогресс крафта. Строка состояния отображает время, FPS, работающие станки, предметы в пути и выпуск.

Возврат жидкости дополняет внешнюю поставку. Расчётная скорость описывает установившееся производство: при запуске пустые линии и буферы требуют времени на заполнение. Полностью замкнутый жидкостный цикл с возвратом побочного продукта получает в симуляции начальный запас 50 м³. В игре стартовый запас нужно обеспечить самостоятельно. Повторный запуск симуляции сбрасывает её состояние.

### Сохранение проекта

«Скачать проект» сохраняет JSON с настройками, модулями, оборудованием и логистикой. «Открыть проект» загружает совместимый JSON и проверяет его данные. Это формат приложения, а не игровой файл чертежа. Приложение также использует локальное хранилище браузера для восстановления проекта; JSON удобен для переноса и резервной копии.

## Бизнес-сущности

| Сущность | Значение |
| --- | --- |
| Ресурс / продукт | Предмет или жидкость с идентификатором, названием, иконкой и единицей измерения. Может быть сырьём, промежуточным продуктом или конечным выпуском. |
| Рецепт | Тип оборудования, длительность цикла, входные и выходные партии и скорости при 100%. Возможны альтернативные варианты и несколько продуктов на выходе. |
| Производственная задача | Выбранный рецепт, целевой выпуск, размеры, ограничения этажей и транспорта, настройки модулей и внешних поставок. |
| Станок | Конкретный экземпляр оборудования с рецептом, частотой, энергокристаллами, размерами, положением, этажом и портами. |
| Производственная группа | Станки одного продукта внутри плана; объединяет их нагрузку и участвует в размещении и логистике. |
| Модуль | Самостоятельная компоновка в ограниченном объёме: станки, этажи, локальные трассы, входы и выходы. |
| Этап производства | Часть цепочки, представленная модулем или несколькими частями. Позволяет рассматривать производство последовательно. |
| Этаж | Уровень размещения. Высота определяется оборудованием и запасом; фактически используемое число этажей может быть меньше разрешённого максимума. |
| Порт | Точка входа или выхода ресурса у станка или логистического узла. |
| Логистический узел | Разветвитель либо объединитель потоков между портами. |
| Трасса / связь | Направленная лента или труба с ресурсом, скоростью потока, геометрией, длиной и пропускной способностью. |
| Внешняя поставка | Ресурс, поступающий из-за границ рассчитываемого производства. |
| Межмодульная поставка | Передача ресурса с выхода одного модуля на вход другого; учитывается отдельно от внешней подачи. |
| Обратная связь | Возврат побочного ресурса на предыдущий этап. Создаёт цикл и может требовать стартового запаса. |
| Проект | Задача вместе с рассчитанными модулями и связями; единица сохранения и загрузки. |
| Состояние симуляции | Текущее время, запасы, прогресс станков, ресурсы в пути и накопленный выпуск. Отделено от расчётного плана. |

## Структура проекта и деплой

`public/` содержит только файлы браузерного приложения: HTML, CSS, JavaScript, Web Worker и иконки. Их относительные пути позволяют размещать приложение как в корне домена, так и в подпапке.

| Папка | Назначение |
| --- | --- |
| `public/` | Приложение, каталог рецептов, расчёт, граф, 3D, симуляция и `assets/items/`. |
| `scripts/` | Локальный сервер, подготовка статической версии, обновление каталога. |
| `tests/` | Автоматические проверки; `fixtures/` — сохранённые заводы для воспроизведения случаев. |
| `data/` | Исходные игровые данные, переводы и индексы иконок для обновления каталога. |
| `benchmarks/` | Отдельный стенд производительности и результаты замеров. |
| `docs/` | Описание формата проекта, отчёт о производительности и скриншоты. |
| `logs/` | Локальные логи; исключены из Git. |
| `dist/` | Готовый статический сайт; создаётся сборкой и исключён из Git. |

Для подготовки к публикации:

```sh
npm run build
# либо без npm:
node scripts/build.cjs
```

Загрузите содержимое `dist/` на любой статический HTTP-хостинг. Команда сборки — `npm run build`, каталог публикации — `dist`. Сервер Node.js для опубликованной версии не нужен: вычисления и сохранение проекта выполняются в браузере. Нужен HTTP(S), корректная отдача JavaScript и поддержка Web Worker; открытие через `file://` не является штатным запуском.

Тесты, исходные игровые данные и скриншоты в сборку не входят. Сохранённые проекты находятся на устройстве пользователя и автоматически не переносятся между адресами сайта; для переноса используйте JSON-экспорт.

## Проверки и ограничения

Все тесты:

```sh
npm test
```

Проверка отдельной подсистемы без npm:

```sh
node --test tests/graph.test.cjs
node --test tests/simulation.test.cjs tests/fluid.test.cjs tests/overview.test.cjs
```

Замеры производительности: `npm run benchmark`, затем [http://127.0.0.1:5174/](http://127.0.0.1:5174/). Подробности — в [отчёте о производительности](docs/performance-report.md).

Поиск размещения эвристический: неудача не доказывает, что допустимой компоновки не существует. Размеры и геометрия оборудования упрощены. Симуляция жидкостей моделирует направленную транспортировку с сохранением объёма, а не полную игровую гидравлику. Поиск и сложность проекта ограничены для сохранения отзывчивости; при устойчивой просадке FPS симуляция может остановиться с пояснением.

## Firebase Hosting

Опубликованный сайт: https://sf-builder-3d.web.app

Проект Firebase: `sf-builder-3d`. Конфигурация — `firebase.json` и `.firebaserc`.

После входа через `firebase login` повторная публикация выполняется командой:

```sh
firebase deploy --only hosting
```

Перед публикацией автоматически запускается `node scripts/build.cjs`. Токены авторизации в репозитории не хранятся.
